Moment pools and aliasing

API reference | Storage guide

Use storagemomentsplan to allocate node moments and checkmomentaliasing to inspect a map's layout. The lower-level allocation and pointer helpers are also listed here because their source docstrings explain that layout. They are implementation details, not an alternative ownership contract for custom arrays.

H2Factory.alignmentslack — Method
alignmentslack(moment) -> Int

Return the worst-case alignment padding for moment, in elements. Buffer allocation adds this to numberofentries(moment) so the last wrapped array remains inside the pool.

H2Factory.allocatemomentbuffers — Method
allocatemomentbuffers(aggregateplan, aggregatetranslateplan,
                      aggregatetree, aggregatetranslatetree,
                      AggregateMomentType, AggregateTranslateMomentType,
                      aggregatemomentsize, aggregatetranslatemomentsize) -> NamedTuple

Allocate the three shared pools (evenbuffer, oddbuffer, aggregationbuffer), sized to hold both plans' moments. Even/odd are sized to the larger of the two plans' per-parity needs (they reset to the pool base per level and are reused across levels and across sides); the aggregation pool holds every stored moment. Sizes come from calculatememoryrequirements – the single source of truth, so the pools cannot be sized inconsistently with what materializemoments wraps into them.

Each plan is sized against its own tree: for a BlockTree/Petrov map aggregatetree and aggregatetranslatetree are the trial and test trees, and this is the same tree materializemoments later wraps that plan's moments with – so a size functor that actually depends on the tree cannot under- or over-allocate one side. (Every current size functor ignores its tree argument, so this is a robustness guarantee for a future one, not a change to any present result.)

H2Factory.checkmomentaliasing — Method
checkmomentaliasing(testmoments, trialmoments, buffers, plans; trees) -> MomentAliasingReport

Lower-level form: check a moment layout directly, without a map. buffers is the (evenbuffer, oddbuffer, aggregationbuffer) NamedTuple the moments were wrapped out of; plans is any object exposing the four plan fields (trialaggregationplan/testdisaggregationplan/ testaggregationplan/trialdisaggregationplan), e.g. an H2Trees.PlanSet or a NamedTuple; trees is (test=..., trial=...).

Runs Tier 1 (physical extents) then Tier 2 (traversal lifetime). See the file header for why both are needed: geometry alone cannot tell a sanctioned overlap from a fatal one.

source
H2Factory.checkmomentaliasing — Method
checkmomentaliasing(A) -> MomentAliasingReport

Check the pooled moment layout of a constructed H2 map A for aliasing that would corrupt a matvec.

It reads moments, pools, plans, and trees through the map accessors. A must retain its pools; see momentbuffers. The check is read-only and runs no matvec. It takes O(n^2) in the number of moments, so use it as a diagnostic rather than inside a matvec.

report = checkmomentaliasing(A)
report.ok || foreach(println, report.findings)

report.ok is false only for :error-severity findings. See MomentAliasingReport.

H2Factory.checktranslatingnodesstored — Method
checktranslatingnodesstored(translatingplan, extents, side) -> findings

Every node whose moment is read by a deferred I2O translation must have moment extents, all in stored memory.

A deferred translating node left in transient scratch is overwritten by the next same-parity level long before the translate phase reads it – the aggregation pass has already moved on. The result is a silently wrong answer, not a crash, and from the outside it is indistinguishable from a translator bug. This is the exact failure class the Petrov mul! investigation burned time on.

Applies only where the translation is deferred (see _deferredtranslatingnodes); a fused AggregateTranslatePlan reads its moments in the same pass that writes them, so transient storage is correct there and no requirement is imposed.

side names the side that owns the translating nodes' moments: a deferred translation is performed by a disaggregation plan but reads the moments the aggregating side produced, so the two are opposite.

H2Factory.materializemoments — Method
materializemoments(slots, tree, MomentType, momentsize, buffers) -> Dict{Int,<:AbstractMoment}

unsafe_wrap each planned MomentSlot into its pool, returning the node => moment dict. The even/odd pointers reset to the pool base at each new level (transient scratch is reused level to level); the aggregation pointer only ever advances (stored moments persist for the whole matvec). slots is ordered by (level, node), so the per-level reset lands on level boundaries exactly as the pool sizing in allocatemomentbuffers assumed.

H2Factory.momentextents — Method
momentextents(momentsdict, tree, side, pools) -> Vector{MomentExtent}

Every wrapped array backing every moment in momentsdict, as byte extents classified by pool. side is :test or :trial. Levels come from tree, so the extents carry the parity the reuse argument turns on.

H2Factory.planmomentstorage — Method
planmomentstorage(plan[, storenode]) -> Vector{MomentSlot}

Describe an aggregation plan's pooled moment layout as an ordered list of MomentSlots – which pool each node's moment belongs to – WITHOUT allocating or wrapping anything. This is the "plan" stage of storagemomentsplan: a plain value that can be inspected before any pointer exists.

Ordered by (level, node) exactly as materializemoments walks it, so the description and the wrap it drives agree by construction. storenode defaults to the plan's own predicate – an AggregatePlan stores its translating nodes, an AggregateTranslatePlan stores nothing.

H2Factory.storagemomentsplan — Method
storagemomentsplan(testaggregationplan, trialaggregationplan, tree, MomentType, momentsize)

Allocate node moments as views into pooled buffers. Return (buffers, testmoments, trialmoments).

The aliasing contract

Moments share three memory pools:

  • aggregationbuffer holds stored nodes for the whole matvec.
  • evenbuffer and oddbuffer hold temporary moments, reused by levels of the same parity.

Temporary moments are live only across adjacent levels. Stored moments may be read later by I2O or disaggregation, so they must not overlap other live moments.

checkmomentaliasing checks the assumptions that make reuse safe:

  • Aggregation levels are contiguous.
  • Nodes read after aggregation are stored, not temporary.
  • Nodes at the same level do not share a slice.

Sharing Between Sides

Test and trial temporary moments may share memory. Their phases run one after the other, so they are not live at the same time. Deferred I2O reads use stored moments. The aliasing check reports cross-side temporary overlap as :info.

Layout / allocation / materialization

planmomentstorage assigns slots to pools, allocatemomentbuffers allocates the pools, and materializemoments wraps each slot. The plan can be inspected before allocation.

Ownership

buffers keeps the wrapped memory alive. Keep it for as long as any moment view is in use; the views do not keep the backing pool alive by themselves.
